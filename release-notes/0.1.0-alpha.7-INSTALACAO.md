# Instalação — HappyTreeNode 0.1.0-alpha.7

## Primeira instalação

1. Baixe `HappyTreeNode-Setup-0.1.0-alpha.7-win-x64.exe` pela release oficial: https://github.com/marcelocorni/happytreenode-releases/releases/tag/v0.1.0-alpha.7.
2. Execute o Setup no Windows de 64 bits e siga as instruções. Os atalhos permitem abrir o Cliente, o Servidor Local e a desinstalação.
3. Inicie o Servidor Local e abra **HappyTreeNode - Cliente**. O endereço local normalmente é `http://127.0.0.1:5078`.
4. Em **Conta e licença**, entre com a conta cadastrada no Portal. O uso exige avaliação ou licença válida. O mesmo usuário pode manter uma sessão ativa do Servidor Local.
5. Abra o projeto **Exemplos HappyTreeNode** e consulte o Manual pelo botão do aplicativo.

## Atualização

Encerre o **Servidor Local** antes de executar o instalador. Fechar apenas o navegador não encerra o servidor. Mantenha a pasta de instalação anterior e siga o Setup; os projetos, arquivos, credenciais e perfis do navegador ficam separados do programa e são preservados.

Se desejar, use o backup do workspace antes da atualização. A restauração do backup é destinada à instalação original; a transferência entre computadores deve usar a exportação/importação de workflows e a reconfiguração dos recursos necessários.

As versões são cumulativas. Não é necessário instalar todas as versões intermediárias. Esta release não deve ser instalada em paralelo com outro Setup do HTN na mesma pasta.

## Conferir o instalador

No PowerShell, execute na pasta do download:

```powershell
Get-FileHash .\HappyTreeNode-Setup-0.1.0-alpha.7-win-x64.exe -Algorithm SHA256
```

Compare o resultado com:

```text
b63c00fab8f9a5e080d90f630ea551956c7064dd80baec747e3f1bf90c7bc0b0
```

O arquivo tem **295.328.313 bytes**. O checksum e o manifesto da mesma release contêm esses dados.

## Recursos desta versão

Os exemplos novos são **43 — Emitir SSL com conferência do DNS**, **44 — Conferir e assinar um relatório PDF** e **45 — Enviar relatório com assinatura de e-mail**. Baixe os arquivos de demonstração pelo Manual e siga as instruções de cada cenário.

Contas, certificados privados e senhas devem ser cadastrados no seu projeto. Esses dados não acompanham workflows exportados. Para conferir uma identidade OpenPGP, o destinatário deve comparar a impressão digital da chave pública por um canal confiável. O certificado fictício de PDF do exemplo serve somente para demonstração.
